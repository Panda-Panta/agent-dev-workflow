# 文件分类、产物清理与自动化

任务开工检查资源，以及新增输出、脚本或文档、调整构建/打包流程或清理文件时读取本文件。沿用项目实际目录和工程命令；本规范不授权删除用户数据、接管共享输出或改变发布条件。安装目录的替换、备份和回退仍按 [交付与同步](delivery.md) 执行。

## 开工前检查可复用资源

在方案定稿和派工前检查任务共用资源，各模块实施前补查模块特有资源：

1. 从根 README、计划/结构索引和工程命令定义定位现有工具、文档、样例及领域 skill，再搜索候选目录并读取相关内容；沿用已知入口，不反复扫描全库或只按文件名判断可用。
2. 对照当前源码/配置确认适用版本、输入输出、依赖、参数、执行目录与副作用。文档陈旧或与实现冲突时标记并核实；找到文件只证明它存在，不代表内容准确或工具已验证。盘点优先读定义与已有证据，不盲跑安装、删除、发布等有副作用的命令。
3. 优先复用适用的命令和资源，其次合理扩展，确认缺口后再新增；记录选用入口、约束或未采用的具体原因。个人小任务在现有计划/日志写一行即可，不新增资源台账。
4. 主 agent 将已检查的共用入口、可复用命令、已知缺口和使用约束交给 subagent，明确本模块仍需检查的资源；子 agent 在模块实施前完成定向补查，发现不适用或冲突时回报并调整，不重复全仓盘点。部分检查不能标为全部完成，随后按任务风险验证实际使用结果。

## 映射布局并分开存放工具和文档

结合资源检查，在现有结构索引中登记类别对应的路径、生成命令和使用者。目录名不同但职责清楚就复用；工具代码与详细文档各有唯一维护入口，彼此链接。根目录保留 README、规则、计划/结构入口及工程所需配置；简短 `--help`、docstring 和工具包局部 README 可就近保留，需独立维护的详细工具说明放文档目录。小项目的用户使用说明可完整保留在根 README，后续拆分时留下链接，不复制多份正文。

| 类别 | 可选位置示例 | 存放边界 |
| --- | --- | --- |
| 源码与运行资源 | `src/`、`assets/`、模块目录 | 维护输入；普通构建输出不混回源码，项目约定的生成源码保留既有位置并标明生成命令 |
| 文档 | `docs/usage/`、`docs/development/`、`docs/changes/`、skill 的 `references/` | 按读者和用途分类，根入口链接唯一正文；详细工具说明链接可执行入口 |
| 长期自动化工具 | `scripts/`、`tools/`，按需分 `build/`、`test/`、`maintenance/` | 可复用、随源码维护的工具代码；使用入口链接对应详细说明 |
| 构建中间产物 | `build/<module>/`、`out/build/<task>/` | 编译、转换、打包暂存等可重建结果 |
| 最终版本产物 | `dist/<version-or-candidate>/`、`artifacts/releases/` | 可交付文件及其来源、清单；候选与已发布状态明确 |
| 测试报告与诊断证据 | `artifacts/tests/<task>/`、`artifacts/diagnostics/<issue>/` | 原始日志、截图、转储和报告；按任务/问题关联来源 |
| 任务临时试验 | `.work/<task>/`、`tmp/<task>/` | 一次性工具放 `scripts/`，记录/说明放 `records/` 或 `docs/`，生成结果放 `outputs/`；不作为长期入口 |
| 缓存 | 工具既有缓存目录、`.cache/<tool>/` | 可重建的加速数据，与制品和用户数据分开 |
| 回退备份 | 项目既定备份位置，按目标/版本分组 | 已核验的恢复材料，避免被通用构建清理覆盖 |

以上是职责映射，不是必建目录清单。小项目可把中间产物、报告和临时试验放在一个工作目录的不同子目录；最终交付制品仍与临时杂物分开。随数量增长再按用途、模块、任务或版本分组，避免把所有文件平铺到根目录或同一个 `output/`。已有混放先核对调用、链接和使用者，在本次范围内渐进归位并更新引用；不为套用示例批量搬迁、建立空目录或开展无关重构。

## 生成前确定输出与来源

- 执行构建、转换、测试或批量生成前，确定输入、输出目录、覆盖范围和归属；优先使用工程命令已有的输出参数。工具固定写入某目录时明确登记，不能假设换工作区就已隔离它。
- 并行任务使用各自的任务/候选目录，不共享默认输出、临时文件名或测试数据。无法隔离的输出由指定负责人串行生成、校验和清理；subagent 只处理自己拥有的产物。
- 制品目录按候选来源管理，沿用 [交付规则](delivery.md) 记录源码状态、版本、生成命令和产物清单/hash。源码含未提交内容时如实记录，不能把旧输出或混入其他候选的文件当成本次构建。普通临时文件不必逐个建立发布级清单。
- 按 [交付规则](delivery.md) 确定运行资源和明确需要的文档清单，再组装并检查发布包；调试转储、试验输入、缓存、开发记录和私人配置不随目录整包混入。项目要求分发的许可证等文件仍纳入清单。
- 按项目约定维护忽略规则，避免提交生成垃圾。被忽略、未跟踪或位于产物目录都不构成删除授权，也不证明文件能够重建。

## 在明确节点清理

| 触发点 | 应执行的整理 | 保留条件 |
| --- | --- | --- |
| 本任务试验结束或路径已放弃 | 及时移除本任务已无用途的一次性文件 | 保留未解决问题的复现输入和证据 |
| 新构建成功并验证替代关系 | 清除已被替代且不再使用的中间产物 | 正在使用、后续步骤依赖或无法重建的内容先保留 |
| 交付验证完成 | 按项目保留策略清理过期候选、重复包和过期报告 | 保留使用中的版本、必要回退和仍有支持责任的版本 |
| 问题关闭、支持期或回退期结束 | 核对证据和备份是否仍需保留，再清理到期内容 | 未结问题、审计/支持要求和未验证的替代备份不能略过 |
| 结构审查或缓存确需回收 | 处理已确认废弃文件；缓存优先用工具自身命令 | 不扩大到全局缓存、其他项目或他人的文件 |

没有既定保留策略时，可在现有交付记录中采用“当前可用版本与最近一个已验证回退版本”的轻量基线，并保留未结问题所需证据；多版本支持、离线恢复或共享责任需要更多版本时以其要求为准。备份也有保留条件，不用无限改名、压缩或搬入 `archive/` 代替清理。任务结束或交付时执行相应整理，不为本规范另建后台定时清理任务。

每次清理按以下顺序处理：

1. **确定对象。** 列出具体文件/目录、归属、生成者和废弃依据，核对用户修改、在用进程及其他任务依赖。不能单凭修改时间、扩展名、名称陌生、未跟踪状态或一次搜索无结果判废弃。
2. **排除保留项。** 用户文件、其他任务文件、必要回退和未结问题证据不纳入通用清理。未知项只暂停该项并记录缺口，其余已确认项目继续；缺少该项授权时说明具体对象和影响，不增加全任务例行审批。
3. **验证边界。** 解析真实绝对路径和链接目标，确认全部对象位于已确定的清理范围内；递归操作不能跟随 junction/symlink 越界。预览后执行前重核文件状态，发现对象变化就重新核对该项。
4. **按对象执行。** 可重建且归属本任务的废弃输出，按已核对清单及时清除。源码、长期脚本或文档则先查静态/动态引用、构建/打包配置、文档入口与实际使用方式；确认废弃后作为正常可审查差异删除，同步移除引用并运行受影响检查，不长期注释或保留“旧版”副本。
5. **核对结果。** 检查实际移除范围、剩余所需文件和受影响入口，记录保留例外与后续条件。Windows 使用同一 shell 的原生安全路径参数，避免字符串拼接删除命令；安装文件清理仍需遵守原有清单差集、备份和恢复要求。

## 主动编写并使用有价值的脚本

- 根据开工资源检查优先复用适用的工程命令和工具。遇到重复步骤、多文件变换、容易抄错的检查或需要可靠重跑的操作，主动补足自动化并在本任务使用；不把可执行工作反复写成长串手工指令，也不为一条可靠命令搭新框架。
- 预期持续复用的脚本进入已有 `scripts/`、`tools/` 或等价位置，按用途适度分组并随源码维护；一次性探查脚本放任务的 `scripts/`，结束时按上述条件清理。试验升级为长期入口时补齐参数、依赖和验证说明，工具与详细文档分别归位并互相链接。
- 参数化输入、输出及必要选项，提供简短帮助、清楚的成功/失败退出码和可定位的错误信息；明确覆盖与重跑行为。使用项目相对路径、配置或环境变量，不写死个人绝对路径，不把秘密写入源码、参数日志或产物。
- 批量删除、覆盖或部署先提供 `preview`/`dry-run`，或等价的具体操作清单；执行前重核目标和状态。预览不等于执行完成，也不替代既有授权。已有可靠工程入口能满足需要时，不另造通用删除脚本。
- 实际运行脚本并核验结果，至少覆盖正常路径及与操作风险相关的关键失败路径，例如输入缺失、目标越界、生成失败不继续部署。破坏性行为可先用隔离夹具验证，再在已授权范围实际执行；无法执行的环节写明未验证，不能只检查语法或退出码就宣称目标已实现。
- 外部命令失败时保留原因并停止依赖步骤，核对真实状态后才有限重试。避免最后一步成功掩盖前面的失败，避免重复执行已成功的删除、发布或安装。

## 只记录维护所需信息

在现有结构索引、开发指南或交付记录补少量对应关系：**类别 → 实际目录 → 工具/文档入口或生成命令 → 保留或清理条件 → 负责人**。目录、命令或资源适用范围变化时同步更新，根入口仍可找到正文；不为本规范强制新增一套文件。

交付前核对本任务新增文件是否归位、制品是否对应实际候选、无用试验与过期输出是否已处理、脚本是否真正运行，并记录有理由保留的例外。各自产物由其拥有者处理，共享输出由既定负责人协调；主 agent 汇总本任务结果，不清理其他贡献者的工作。文档分工和事实记录仍按 [文档规范](documentation.md) 维护。
