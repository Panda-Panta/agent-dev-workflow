# 领域知识与任务流程沉淀

## 何时记录

任务完成前，对照开工时找到的现有正文与本次证据，检查是否出现有复用价值的新流程、缺失步骤、易错约束或失效说明。除专有文件格式、复杂算法、跨模块状态机和兼容行为，也包括实际完成的工具调用、环境准备、资源重建、录制等操作流程；有缺口就补到合适的领域 skill 或文档，不等待用户再次要求。现有记录已足够且仍适用时，在任务记录中简记“已检查，无新增知识”即可。

未完成、失败后仍未恢复或关键结果未验证的任务，先在日志/交接中保留已知事实、草稿步骤和下一步，不能写成成功验证过的标准流程。非开发任务的知识记录只执行资源核对、必要记录与文档检查，不因此启动开发计划、模块派工或软件发布。

## 选择唯一正文

- 用户要求沉淀通用开发经验时，提炼计划、协作、日志、导航、验证和交付中的跨项目方法，合入现有对应章节；项目业务、专用格式和具体工具的实现约束留在项目文档或领域 skill。先比较已有条款，只补缺口或修正失效内容，不将本次全部技术细节另写成通用专题。
- 先读取相关正文，确认适用版本和内容缺口。简单流程补现有模块文档、使用说明或 README；复杂、稳定且易错的领域流程优先补已有领域 skill 的规则或参考说明。
- 没有合适记录入口时，先在当前项目/工作区的文档目录留下可发现的说明；普通小任务几行足够，不为每个按钮或一次性操作新建 skill。需要创建专有领域 skill 时按开发任务的实际范围处理，沿用项目技能目录（没有约定时为 `.agents/skills/<project>-<domain>/`），一个稳定领域只维护一个入口。
- 不因知识沉淀擅自写入全局记忆、创建其他全局 skill 或修改 AGENTS/运行配置；只有当前任务已包含相应创建、接入或安装范围时才处理该范围。不要把凭据、临时设备句柄或本机私有路径固化到通用流程；易变值使用占位参数，并说明如何重新发现。
- 知识正文回答“下次怎么做”；日志回答“本次做了什么、结果如何”，只链接知识正文和证据。工具实现放 `scripts/`、`tools/`，长说明放 `docs/`、`references/`，相互链接，不复制工具源码或另存一份冲突说明。

## 按需记录的内容

只保留本流程必要的内容，不要求每次填满模板：

- 目的、适用范围/版本、权威来源，以及需要重新核对的条件。
- 实际工具入口、调用方式、必要参数与工作目录，输入输出和关键约束；环境依赖、权限、配置及准备步骤。
- 准备、预检/试运行、正式执行和正常结束的必要次序；产物位置、可观察的成功判据及验证办法。
- 已遇到的失败、恢复与资源清理方法；未试过的替代方案须标为未验证，不编造恢复成功。
- 本次执行证据、验证环境/版本与局限。复用可访问的记录摘要或链接，不抄整段工具日志。

例如游戏录制，可记录如何发现并调用录制工具、准备设备/窗口与输出目录、检查音视频来源、试录、开始/结束正式录制、核验文件及释放资源。这里只规定记录结构；具体命令、参数、设备和结果必须来自该任务实际证据，不能借另一个会话的描述编造。

领域 skill 仍需简洁的 `name`、明确触发条件的 `description`，以及领域语义、输入输出/单位/状态、不可破坏的约束和重要边界例；长细节链接到 `references/`。源码、配置和数据是实现事实来源，不复制易变 API 清单。机制变化时一起修订适用版本、步骤、例子和验证依据，标明旧流程被替代的关系。

## 验证与接入

检查记录的入口、链接、参数、版本和证据是否一致；技能格式检查按当前可用的 skill-creator 执行。已实际完成且仍对应当前版本的验证证据可以复用，不为补文档重复危险、昂贵或有副作用的操作；必须区分本次运行、历史证据和未验证部分。

新增或改变行为的脚本按风险在安全样例上验证；仅改说明或引用，不强制重跑未变脚本。新建或实质改变复杂工作流时，按风险让独立 agent 做隔离任务或场景核对；每次小型 skill 文档修改不强制完整实操。审查推演不能当作真实执行通过。

更新现有文档导航/结构索引，使下次任务能找到正文；开发任务的计划或日志链接相关领域记录。相关文档和项目 skill 随本任务交付规则同步，运行时无需 skill 的软件不复制开发 skill 到安装目录。记录流程不扩大远端、安装或发布授权。
