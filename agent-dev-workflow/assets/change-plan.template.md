# 更新计划：填写任务 ID 和名称

> 个人小任务可直接在现有计划写一段及实际结果，不必另建本文或填齐表格。沿用项目模式、授权和检查入口，只有变化时补记；完整规程读取 `agent-dev-workflow`。

## 目标与验收

- 用户真实目标、受支持场景、现有行为、范围及非目标：
- 问题/根因证据与最小正确方案：未确证原因标为假设并给出核验动作，新需求无需编造故障根因。
- 真实行为的通过条件、能暴露其失败的检查及当前证据缺口：
- 基线版本、用户已有修改；影响验收的未知及可继续的工作：
- 相关工具/文档/样例/领域 skill 的入口、适用性与副作用、复用决定及待查项：任务前定向检查，短任务一行即可。

## 影响与兼容

- 新行为、保持的旧行为与回归样例：
- 允许改变的行为或契约、受影响调用者/数据、确认依据与迁移/回退：沿用已有明确决定或授权。
- 模块边界、共享契约及实际修改路径：
- 新增复杂度的实际需求/失败证据、成本收益及保留现有设计的可行方案：存在实质取舍时填写。

## 实施与并行

主 agent 自主模块化，按 skill 的“并行派工与集成”确定接口、依赖和唯一写入归属。独立模块默认由至少 2 个 subagent 同批实施；小修改可用一段记录实际模块、agent、批次与状态。

| 模块 / 工作包 | 输入输出 / 交付位置 | 前置依赖 / 批次 | 独占文件或目录 / agent | 验收 | 状态 |
| --- | --- | --- | --- | --- | --- |

- 共享文件负责人、集成顺序及重要变更的独立审查：
- 派工资源入口、已知限制与模块需补查项：
- 具体受限原因、实际调度及后续安排：仅适用时填写，不以审查或串行执行冒充模块并行实现。
- 自动化脚本与实际输出位置：沿用文件分类映射，工具代码、详细说明、产物/报告/临时区分别存放。
- Git 安排：默认 `test` 开发/集成/验证；特殊分支仅在需要时记录用途名称、负责人、基线、合入目标及结束条件。Git 操作由主 agent 串行协调。

## 验证与文档

- 实际检查命令/操作、工作目录、退出码、版本及证据：覆盖新行为和受影响旧行为，按需要构建或运行。
- 模拟、静态与真实行为各自的覆盖范围；未验证项及下一步：真实目标未验证不记完成。
- 环境/依赖变化及复现范围；适用 CI 的提交与结果：未变则引用已有入口。
- 计划、结构索引、开发日志、版本变更说明和受影响使用文档：记录实际更新/核验或检查无变化。
- 新流程/知识纠错：记录唯一文档或领域 skill 正文入口及验证范围，日志只链接；无新知识可记“检查无变化”，未验证内容留交接草稿。

## 交付结果

按 skill 的“交付与双端同步”及既有配置执行，只记录适用环节。程序与分发内容未变的纯文档更新，仅核验并同步文档维护位置，不重建或安装相同程序；知识记录不新增发布授权。
