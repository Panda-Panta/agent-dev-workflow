## 软件开发流程

开发前读取已安装的 `agent-dev-workflow/SKILL.md`（`$agent-dev-workflow`），再读下列项目入口。用户当前更具体的要求优先；续作沿用已有决定、授权和未完成记录。将本段合并进现有 AGENTS.md，保留其他规则。

- 技术决策、验证与审查读取该 skill 的“决策与证据原则”：目标优先、复杂度相称；真实行为优先；后果与证据匹配。仅问答/只读审查不启动实施或同步，非开发流程沉淀只使用知识记录分支。
- 沿用项目的个人/共同模式。个人小任务复用现有计划一段及实际结果，不强制表格、新文档、PR、CI 或例行审批；共同任务明确认领、审查、合并与发布职责。
- 主 agent 自主模块化；可独立实施的模块默认由至少 2 个 subagent 同批并行开发，按文件/输出独占分工。真实受限时按 skill 记录原因；不以审查或串行执行冒充并行实现。subagent 只执行派工范围，不递归启动完整流程或自行发布。
- 有 Git 时默认在 `test` 开发、集成和验证，通过后以 PR 或平台允许的直接合入更新 `main`；特殊需要可建按用途命名的分支。Git 写入由主 agent 串行协调，具体分支、制品来源与软件同步规则读取该 skill 的“交付与双端同步”引用文档。无 Git 不为此建仓库。
- 任务前定向检查可复用工具、文档和领域 skill；工具代码、详细文档与运行输出分别管理。计划、验证、维护文档、清理及知识沉淀按 skill 执行，不在这里复制流程正文。
