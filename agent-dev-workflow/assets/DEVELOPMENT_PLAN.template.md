# 软件开发计划

> 已有权威计划则复用，并在源码根保留入口。此模板按需取用，不要求填齐所有表格或新建所有文档；个人小更新可只维护现有计划的当前任务段和实际结果。未知项写核验动作，不编造答案。执行规则以 `agent-dev-workflow` 为准。

## 项目与文档入口

- 软件名称、目标用户与真实行为目标：
- 源码根 / Git 根（如有）/ 基线版本及已有用户修改：
- 当前里程碑、状态及增量任务入口：
- 开发模式（个人/共同）与依据；共同模式的任务、审查、合并、发布职责：沿用既有约定时链接即可。
- 权威结构索引、环境/检查命令、交付配置：填写实际入口，允许复用现有根计划或 README 段落。
- 使用说明、开发日志、版本更新说明、重要决策与交接：仅列实际适用入口。

## 范围与需求

- 受支持场景、现有产品行为、输入输出、非目标及实际约束：
- 问题/根因证据；未确证假设及核验动作：新需求无需编造故障根因。

| 功能 ID | 用户场景与功能 | 优先级 / 状态 | 所属模块 | 可观察验收标准 |
| --- | --- | --- | --- | --- |

## 资源与方案

- 相关工具、命令、文档、样例、领域 skill 的入口；适用性/副作用、复用决定和缺口：任务前定向检查，小任务一行即可。
- 最小正确方案、模块边界、入口与数据流：按 skill 的“决策与证据原则”选择；有实质取舍时补充保留现有设计的可行方案。
- 新增防御/抽象/依赖或技术替换的实际需求或已证实失败、收益与维护成本：仅适用时填写。
- 文件分类与保留条件的唯一映射入口：确认工具代码、详细文档、构建中间文件、最终产物、报告、临时区与备份位置；不复制目录树。

## 数据与兼容性

- 既有行为不变量、配置/存储/外部接口及版本、旧样例：
- 本次允许的行为或契约变化、确认依据及受影响调用者/数据读写者：已有明确要求或授权可引用。
- 读写兼容、迁移、数据保护与回退：按实际变化填写。

## 任务与并行批次

主 agent 自主划分工作包，按 skill 的“并行派工与集成”确定接口、依赖和唯一写入归属。独立模块默认由至少 2 个 subagent 同批实施；小任务可用一段替代表格，保留实际分工与结果。

| 模块 / 工作包 | 输入输出 / 交付位置 | 前置依赖 / 批次 | 独占文件或目录 / agent | 验收 | 状态 |
| --- | --- | --- | --- | --- | --- |

- 共享接口/文件负责人、集成顺序、重要变更的独立审查：
- 派工资源入口、已知限制及模块需补查项：
- 受限部分的具体原因、实际调度及后续安排：仅适用时填写，不以审查或串行执行冒充并行实现。

## 环境与验证

- 真实工具链/版本、依赖锁文件、配置示例及启动/检查/构建入口：复用现有命令；已有 CI 时链接其检查。
- 适合复用或改进的自动化步骤、脚本输入输出与实际验证：按需填写，沿用既定工具目录。

| 验收项 / 受影响旧行为 | 命令或实际操作 / 样例 | 能发现的目标失败 / 通过条件 | 证据类型、结果及缺口 |
| --- | --- | --- | --- |

记录实际命令、工作目录、退出码与版本；区分模拟、静态、构建、运行和真实端到端证据。真实目标尚未验证时写明缺口及下一步，不填写完成。

## 交付与回退

- 交付配置入口；已授权远端与软件目录的用途、更新清单和数据保留清单：
- 有 Git 时：默认 `test` 开发/集成/验证、`main` 接收验证结果；记录 test 候选 SHA、PR 或允许的直接合入方式、main 实际 SHA 与适用检查。
- 特殊分支（仅需要时）：按用途命名，记负责人、基线、合入目标及结束条件。
- 制品来源/清单/哈希、目标准入条件、安装文件与运行验证、备份及恢复依据：按适用环节填写。

完整分支和同步规程读取 skill 的“交付与双端同步”，不在计划重抄。无 Git 则记录实际版本；缺失目标和部分完成分别保留真实状态。

## 风险、决策与未知

- 影响验收的假设、证据和核验动作；关键缺口及可继续的工作：
- 超出现有产品行为、架构边界或授权范围的决定与确认依据：仅适用时填写，沿用已有明确决定，不增加例行审批。
- 相关技术债、故障反馈与依赖变更：链接已有待办及处理条件。

## 当前增量与维护结果

小更新在此记录目标、影响范围、分工/批次、验收及交付；较大更新链接增量计划。收尾补实际结果，未执行项保留原因。

- 计划、结构索引及受影响使用文档的更新或检查结论：
- 上次完整结构审查 / 下次条件：默认每个里程碑或累计 5 次交付，可按项目调整。
- 本次文件整理/清理、仍保留的产物与回退材料及依据：
- 新流程或知识纠错的唯一正文入口、验证范围与实际更新：简单方法补现有文档，复杂且易错的稳定流程补领域 skill；无新增可记“检查无变化”。日志只链接，未验证内容留交接草稿。
- 远端、软件目录与未完成工作的结果/证据、接续条件：纯文档更新不重建或安装内容未变的程序。
